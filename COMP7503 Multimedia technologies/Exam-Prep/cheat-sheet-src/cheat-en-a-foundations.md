### Multimedia, communication, and an experiential environment
**Multimedia (多媒体):** the combined use of several media that stimulate one or more of the five senses (sight, hearing, touch, smell, taste) to deliver relevant information to users. e.g. a dentist's "Just lie down, shut up, and open wide" needs the scene to make sense. Each sense gives only partial information. Not just "entertainment/music/photo/video/ebook" (narrow views). Audio/video dominate because humans analyse them well and they are easier to capture/reproduce than smell/taste/touch.
**Computing (计算):** any goal-oriented activity requiring, benefiting from, or creating computing machinery. e.g. a navigation app computing the fastest route.
**Multimedia computing:** utilise signals from multifarious sensors and present to users only the relevant information in the appropriate sensory modality (media). Goals: information sharing on experiences; knowledge extracting from experiences. e.g. a photo app turns photos' time + GPS metadata into a trip route on a map.
**Communication (沟通/传播):** key to share experiences and to create, maintain, sustain and propagate knowledge; across time (preserve/replay), space (remote) and addressee (as many people as possible). e.g. a recorded lecture crosses time; uploading it reaches many students anywhere.
**Invariance table (不变性) (slide):** speech -> none; writing -> time; paper -> time+space; print -> time+space+addressee; telegraph/telephone -> space; radio/TV -> space+addressee; movies/recording/digital media -> time+space+addressee (digital adds machine enhancement/processing); Internet -> time+space+(personalized) addressee.
**Development:** application -> technology -> device: numerical -> ALU -> computer (1960s IBM 1620 "CADET", no ALU, lookup tables); business -> alphanumeric/database -> workstation/server; documents/Web -> connectivity/CPU -> PC/laptop; social/photo -> mobile comms/AV/geolocation -> phone/tablet. CPU, storage, bandwidth, and algorithm progress made audio/video practical.
**Eras:** 1960s IBM 1620 (lookup tables, punch cards) -> pre-1990s text-only PCs -> early 1990s sound cards, 3-D games -> mid-1990s Win95, CD-ROM -> end-1990s every PC is "multimedia" -> today phones have more sensors than humans; 1G voice only -> 3G/4G/5G video.
**Emerging applications (新兴应用):** live spatiotemporal streams are the norm; a holistic picture of events beats silos of isolated data; insights independent of medium/source; only relevant information counts; exploration (browsing) replaces relational database querying. Two aspects: the evolving nature of information and the expected results from computing. e.g. live traffic map vs a static yearly report.
**Amazon example:** (1) orders HK-Taiwan = static count; (2) regions with rapid growth = trend over time; (3) hottest item now = live, constantly changing.
**Multimedia vs Monomedia (单媒体):** monomedia (computer vision, audio processing) analyses one medium; slide's 3 points: (1) multimedia is closely related to how humans experience the world; (2) partial information from multiple media sources is correlated and combined to get complete information about the environment; (3) multimedia computing and communication is fundamentally about combining information from multiple sources in the context of the problem being solved.
**Formal definition:** synchronised sensor streams S_1..S_n of K data types plus metadata (元数据) M_i (annotations, parameters, time, location) -> feature detectors -> features (特征) F_ij (j-th feature stream of S_i) -> integrate and process (association/fusion (关联/融合)) -> insights -> user feedback (query) as a new input stream. Example: photo metadata (time, GPS) -> insight = route of a trip on a map. Bluetooth/NFC are communications, not sensors.
**Experiential environment (体验式环境):** an environment where users directly use their senses to observe data and information of interest related to an event, and interact naturally with the data based on their particular set of interests in the context of that event. e.g. swiping through a photo map of a trip to explore where and when each picture was taken.
**Why needed:** current information environments work against human-machine synergy: humans are good at conceptual/perceptual analysis, computers at mathematical/logical analysis. Experiential systems are technically implemented as multimedia systems (integrate, process, output data from different sensory modalities).
**3 properties:** (1) direct and intuitive: holistic picture, no unfamiliar metaphors/commands (swipe to next photo, tap app icon, Kinect); (2) same query and presentation spaces, WYSIWYG (spreadsheet: change a value, see new relationships); (3) consider user state and context (自适应), promote perceptual analysis and exploration (video games: audio + video + touch).

### Experience, perception, semantics, and systems
**Objective of a multimedia system:** process different types of data streams simultaneously as one correlated set representing information/knowledge for solving a problem. e.g. lecture-recording software keeps mic audio and PC screen as one synchronised set.
**Challenge:** discover correlations in the multimedia data; combine partial information from disparate sources into holistic information in a given context. e.g. COVID gate: thermal sensor + camera mask check -> one decision.
**Experience (经验):** direct observation of, or participation in, events as a basis of knowledge. e.g. living through a pandemic.
**Information (信息):** an efficient but abstract communication of experience. e.g. the sentence "wearing a mask is a powerful weapon".
**Knowledge (知识):** accumulated/aggregated experiences. e.g. a doctor's expertise built from many cases.
**Communication process:** sharing experiences and information with others (who may be separated in space and time); we do not communicate the experience itself, so the act of experiencing is lost (mask example); effective communication needs relevant experience.
**DIKW:** data records -> information gives meaningful relationships -> knowledge explains patterns -> wisdom chooses action under goals.
**Dictionary (词典):** a shared and agreed-upon collection of symbols (words) and what they mean: language = words; CS = codes/terms/keys, also dictionary compression; multimedia = percepts (感知元素) (visual dictionary: curves, lines, shapes).
**Objects (对象) / events (事件):** objects capture static components of the world; events represent changes in relationships among objects; audio/video are dynamic (attributes as functions of time). "Person" is an object; "person enters a restricted zone" is an event.
**Perception (感知):** the process of understanding sensory signals to recover useful information; signal + existing knowledge -> information. It generates hypotheses (假设) and selects the best supported; controlled hallucination (受控幻觉) = model-guided interpretation, not arbitrary invention. Without knowledge, no information.
**Neisser cycle (奈瑟知觉循环):** schema (图式) directs exploration -> exploration samples environment -> environmental information modifies schema -> revised exploration. （已有认知指导观察，新的观察又修正认知。） The agent decides what extra information is needed and how to get it. Vase/faces, Dalmatian, and "Wine or Soy Sauce / MTR Mei Foo" show prior knowledge + context drive interpretation.
**Semantic gap (语义鸿沟):** the difference between the information a machine can extract from (perceptual) data and the interpretation a user in a given situation has for the same data. Machine: bits/bytes -> lists/images/audio/video; user: objects/events -> knowledge. Reduce it with content + context + metadata + priors + user feedback; it never fully disappears. Computers see only numbers (25 C), not "hot/cold", until we give thresholds (<20 cold, >28 hot). Transformers succeed because they model context.
**Content (内容) / context (情境/上下文) / metadata:** content = acquired data; context = interrelated conditions in which content is acquired; metadata = "data about data", providing context parameters (photo Exif time/location/camera). Combine content + context.
**Five modules (五大组件):** capture (camera, mic, keyboard, mouse, touch, pressure), storage (disk/flash/optical), network (LAN/4G/5G/Bluetooth/RF), computer/DSP (workstation/server; encode/analyse/fuse), output (LCD, speaker, vibration motor, haptics). Phone call: microphone -> digitize/encode/buffer -> network -> decode -> speaker.
**Four problems (四类核心问题) (slide):** (1) compact representation for storage/communication; (2) effective presentation of vast data; (3) system support for disparate data types; (4) combining streams to get task-essential information. e.g. a video call must compress, display, handle audio + video, and sync them.

### Representation, data, and programming
**Media as data:** sound = 1-D time signal; image = 2-D pixel array; video = ordered image sequence. W x H = spatial sampling, bit depth (位深) = amplitude/color precision, FPS = temporal sampling, bitrate = coded bits per second.
**Pixels:** 1-bit = black/white; 8-bit grayscale = 256 levels; RGB 8 bits/channel = 24 bpp; RGBA = 32 bpp: standard alpha = opacity/coverage; the teacher described the 4th 8-bit channel as a mask (foreground / which window is on top). Colour hex #RRGGBB = 2 hex digits per channel (e.g. #FFCC00).
**Size formulas:** raw image bytes = W*H*bpp/8; raw video multiplies by FPS and seconds; PCM bps = sample rate*bit depth*channels; storage = bitrate*duration.
**Teacher's 3 performance parameters:** resolution (image quality), FPS (fluency; about 24-25 fps is the minimum to perceive motion; 24/25/30 by standard), kbps (compression efficiency, H.264/H.265).
**Worked (class):** 4x4 RGBA at 32 bpp = 16*32 = 512 bits = 64 B; 1080p RGBA raw frame = 1920*1080*4 B = 8,294,400 B about 8.3 MB, x25 for one second of video.
**Synchronization (同步):** streams/clocks must share one time reference.
**Programming paradigms:** procedural programming (面向过程) = steps/control flow (step 1 ... step 10; C); OO programming (面向对象) = class for an object's static properties, methods for events/dynamic behaviour between objects (C++/Java); functional programming (函数式) = state WHAT you want (e.g. "sort this"), not HOW, immutable data, few side effects (like AI coding). Python is multi-paradigm.
**Binary and data structures:** a circuit uses distinguishable physical states (open/closed) for 0/1 (Soviet Setun used 3-state logic). Data structures: list, array, table, set, map; humans do not store experience as vectors -> gap.

### Sampling, quantization, Nyquist, and PCM
**Sinusoid:** x(t)=A cos(2pi f t + phi): A amplitude (振幅), f Hz, T=1/f, omega=2pi f, phi phase (相位) (projection of uniform circular motion); time shift dt -> phase shift 2pi f dt. A complex signal = sum A_k cos(2pi f_k t + phi_k).
**Digitization:** converting a continuous signal into a discrete set of its samples, in both time and signal value. Digitized values are much less susceptible to distortion than analog signals.
**Sampling (采样):** capture the analog signal at regular time intervals (sampling rate fs): x[n]=x(n/fs), Ts=1/fs. Error it introduces = discretization error (离散化误差) (limits the maximum frequency).
**Quantization (量化):** each sample is rounded to a fixed set of integer levels: n bits -> 2^n levels; step Delta about range/2^n, rounding error <= Delta/2 when no overload; error e=x-Q(x) = quantization error. Common depths 8/16/24/32 bits. （采样把时间变离散，量化把幅度变离散；采样率决定最高可表示频率，位深决定幅度精度。）
**Trade-off:** more samples improve temporal density; more bits reduce amplitude error; both increase data and cannot substitute for each other. 1-bit quantization destroys detail. Legacy telephone 8 kHz (bandwidth-limited) vs smartphone higher rates -> better call quality.
**Class example:** 5 s, 1 sample/s, 4 bits -> 5 samples*4 bits = 20 bits; bits = duration*fs*bits/sample*channels.
**Nyquist theorem:** if x(t) contains no frequencies higher than B Hz, it is completely determined by samples spaced 1/(2B) s apart. Nyquist rate (奈奎斯特率) = 2B; Nyquist frequency (奈奎斯特频率) = fs/2. Use fs > 2B (concert: drum low + flute high -> the flute's highest frequency sets B) plus an anti-alias low-pass filter (抗混叠低通滤波器) with margin.
**Why not fs=2B:** x=A cos(2pi B t+theta), Ts=1/(2B) -> x[n]=A(-1)^n cos(theta); phase lost, and theta=pi/2 gives all-zero samples.
**Aliasing (混叠):** different analog frequencies give the same samples: at 32 kHz, 18 kHz aliases to 14 kHz. 44.1/48/96 kHz -> Nyquist 22.05/24/48 kHz. Hearing 20 Hz-22 kHz -> record at >=44 kHz with filter margin; 48/96 kHz help digital filtering/ML, not audible range.
**PCM calc:** 44.1k*16*2=1.4112 Mb/s; 60 s = 10.584 MB about 10.09 MiB, excluding headers. Duration of N samples = N/fs.
