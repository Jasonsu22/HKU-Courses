# Analysis plan — from six sessions to a revision list

## 1. What counts as success

| Task | Success (Y) | Partial (P) | Fail (N) |
|---|---|---|---|
| T1 Historical change | names a change **with** a number/visual | names a change without evidence | cannot find a change |
| T2 Compare sides | both rates **and** both n; comments on n=13 | both rates, no n | wrong side or no rates |
| T3 Terrain view | meaning of the percentage **and** “schematic line” | one of the two | takes it as a real map |
| T4 Profile | estimate, cohort n, observed rate | estimate + one of the two | cannot get a number |
| T5 Interpretation | notices the drop **and** gives a reason to distrust precision | notices the drop only | reads 3% as precise |
| T6 Limitation | one concrete limitation in own words | repeats a label without meaning | none |
| T7 Through time | describes the change **and** compares with the model | describes the change only | calls it stable |
| T8 Connections | names a linked pair **and** reads success | pair only | no pair, or reads a link as a cause |

Uncompleted tasks are counted as **N** for completion rate, even if the participant ran out of time.

## 2. Metrics to report (per task and overall)

- **Completion rate** = (Y + 0.5·P) / 6. Report Y/P/N counts next to it.
- **Median time** (seconds) and interquartile range, excluding N > time limit.
- **Mean confidence** (1–5) and the share of tasks where confidence ≥ 4 but the answer was wrong
  (overconfidence signal).
- **Prompts per session** (mean).
- **Percent agreement** on each of the five closing statements.

Small n: report counts, not just percentages (“5 of 6”, not “83%”).

## 3. Qualitative coding

Code every quote / observation into one of these, then count how many participants hit it:

| Code | Meaning | Typical fix |
|---|---|---|
| `denominator` | reads a rate without its n | make n louder; add “n=” to axis labels |
| `map` | takes the schematic as geography | stronger banner; label the panel “schematic” in the title |
| `precision` | treats the interval/estimate as a guarantee | rewrite the “Reading it” copy; add “historical association” |
| `member-vs-expedition` | confuses the two estimates | rename rows; add a one-line explanation |
| `navigation` | cannot find filters / the panel | move controls; add a hint |
| `empty-state` | confused by “insufficient evidence” | explain what to change |
| `terminology` | “log-odds”, “Wilson”, “cohort” unclear | plain-language labels |

Priority rule:
- **High**: hit by ≥ 2 participants, or any **N** on T2–T5 (the tasks the proposal calls the product path).
- **Medium**: hit by 1 participant and cheap to fix.
- **Low**: cosmetic wording.

## 5. Decision rule for scope

Follow the proposal's fallback order: cut decorative detail, external current indicators and fine-grained
prediction **before** removing route comparisons, denominators, uncertainty or explanatory evidence.
If a revision would affect the model, note it for the report rather than changing the model late.

## 6. What goes in the report

- One table: task, completion (Y/P/N), median time, mean confidence.
- 2–3 verbatim quotes illustrating the two most common misunderstandings.
- A short “revisions made” paragraph with the revision-log rows.
- Threats to validity: 6 participants, convenience sample, one moderator, no audio recording, offline
  laptop only; findings indicate problems, not population estimates.
